## Reading: Key Cybersecurity Terms and Concepts

### Summary
Security/cybersecurity analysts monitor networks for breaches, build 
security strategies, research IT security trends, and work to prevent 
incidents. To do this well, they need a solid grasp of core concepts like 
compliance, frameworks, controls, security posture, threat actors, network 
security, cloud security, and programming.

### Role of an Analyst
- Monitors networks for breaches
- Develops strategies to secure an organization
- Researches IT security trends to stay informed
- Works to prevent security incidents

### Key Concepts (full definitions in glossary.md)
- Compliance
- Security frameworks
- Security controls
- Security posture
- Threat actors (and internal threats specifically)
- Network security
- Cloud security
- Programming (used for automation, traffic review, alerting)

## Reading: Attack Types (Phishing, Malware, Social Engineering & CISSP Domains)

### Summary
Threat actors use several categories of attacks to compromise data and 
systems: phishing (tricking people via digital communication), malware 
(harmful software), and social engineering (exploiting human trust). 
Additional attack types — password, physical, adversarial AI, 
supply-chain, and cryptographic — map to the 8 CISSP security domains, 
showing how attacks are categorized for risk management.

### Phishing Types
- Business Email Compromise (BEC)
- Spear phishing
- Whaling
- Vishing
- Smishing

### Malware Types
- Viruses (needs user action to spread)
- Worms (self-replicates, no user action needed)
- Ransomware (encrypts data for payment)
- Spyware (collects/sells data without consent)

### Social Engineering Attack Types
- Social media phishing
- Watering hole attack
- USB baiting
- Physical social engineering

### Why Social Engineering Works
People are naturally trusting and conditioned to respect authority. Threat 
actors exploit this using: authority, intimidation, consensus/social 
proof, scarcity, familiarity, trust, and urgency.

### Attack Types Mapped to CISSP Domains
| Attack Type              | CISSP Domain(s)                                   |
|---------------------------|---------------------------------------------------|
| Password attack             | Communication and network security                |
| Social engineering attack   | Security and risk management                      |
| Physical attack              | Asset security                                     |
| Adversarial AI                | Communication/network security + identity/access mgmt |
| Supply-chain attack          | Security and risk mgmt, security architecture, security ops |
| Cryptographic attack         | Communication and network security                |

## Reading: Understanding Attackers

### Summary
Threat actors are defined by malicious intent, while hackers are defined 
by technical skill and motivation. Both groups can overlap. Understanding 
who they are and why they attack helps analysts better anticipate and 
defend against threats.

### Threat Actor Types
- **Advanced persistent threats (APTs)** - highly skilled, research 
  targets, stay undetected long-term; target infrastructure or IP
- **Insider threats** - abuse authorized access; motives include 
  sabotage, corruption, espionage, or data leaks
- **Hacktivists** - politically motivated; use tech for demonstrations, 
  propaganda, social change, or fame

### Hacker Types
- **Authorized/ethical hackers** - law-abiding, protect organizations
- **Semi-authorized hackers** - researchers who find but don't exploit 
  vulnerabilities
- **Unauthorized/unethical hackers** - malicious, sell data for profit
- **New/unskilled threat actors** - motivated by learning, revenge, or 
  exploiting known weaknesses using existing tools
- **Contracted hackers** - work for pay, not agenda-driven; can be 
  ethical or unethical, legal or illegal work
- **Vigilante hackers** - aim to protect the world from unethical hackers

## Reading: Controls, Frameworks, and Compliance

### Summary
Controls, frameworks, and compliance work together to manage 
organizational risk. The CIA triad (confidentiality, integrity, 
availability) underpins how security controls are designed. Frameworks 
provide structured guidelines, controls are the safeguards that implement 
them, and compliance ensures organizations follow internal standards and 
external regulations/laws.

### How They Connect
- **CIA triad** - foundational principles for setting appropriate controls
- **Security controls** - safeguards used alongside frameworks
- **Security frameworks** - 4 core components:
  1. Identify and document security goals
  2. Set guidelines to achieve those goals
  3. Implement strong security processes
  4. Monitor and communicate results
- **Compliance** - adhering to internal standards + external regulations

### Key Frameworks & Regulations
- **NIST CSF / NIST RMF** - voluntary U.S. frameworks for managing risk
- **FERC-NERC** - power grid security regulation (U.S./North America)
- **FedRAMP** - standardizes cloud security assessment for U.S. gov't
- **CIS** - nonprofit providing actionable defense controls
- **GDPR** - E.U. data privacy regulation; 72-hour breach notification
- **PCI DSS** - secures credit card data handling, reduces fraud
- **HIPAA** - protects U.S. patient health info (privacy, security, 
  breach notification rules); supported by HITRUST framework
- **ISO** - international standards across tech/manufacturing/management
- **SOC 1 / SOC 2** - reports on user access policies and financial/risk 
  compliance, developed by AICPA

### Takeaway
The tighter an organization's alignment with compliance frameworks, the 
lower its overall risk. Analysts need to stay current on these standards 
since regulations are frequently revised.
